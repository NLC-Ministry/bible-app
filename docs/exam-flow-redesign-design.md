# 大測驗後台流程重新設計

> 狀態：**設計提案，尚未實作**（2026-09-27）。等確認後再拆成實作 issue。
> 目標：12 月底下一次大測驗前，在 staging 完成並驗收。

## 一、現在哪裡亂

一份試卷現在同時有 **9 個互相獨立的開關／狀態**，管理員要自己記住順序和組合：

| # | 開關／狀態 | 在哪裡操作 |
|---|---|---|
| 1 | 試卷狀態：草稿／測驗進行中／已關閉 | 主按鈕 |
| 2 | 預告文已發佈／未發佈（其實發佈的是「公告」） | ⋯ 更多 |
| 3 | 「預告」開關（另一則更早的通知，公告發佈後自動蓋掉） | 公告分頁 |
| 4 | 成績已公布 | 主按鈕 |
| 5 | 自動評分 開／關 | ⋯ 更多 |
| 6 | 複習 開／關 | ⋯ 更多 |
| 7 | 答案詳解 顯示／隱藏 | ⋯ 更多 |
| 8 | 演練作答（草稿時） | 主按鈕 |
| 9 | 撤回成草稿 | ⋯ 更多 |

具體造成的問題：

1. **「草稿」和「預告文已發佈」可以同時成立**（截圖就是這個狀態）：測驗還在編輯，首頁卻已經有卡片 → 管理員的演練作答被卡片當成「已完成作答」（#296）。
2. **同一件事有三個名字**：「預告文」「公告」「預告」。按鈕寫「發佈預告文」，發佈的其實是「公告」分頁的內容；另外還有一個真正叫「預告」的東西。
3. **準備清單混了兩種事**：「題目數對了」是出題的事，「公告已發佈」是對外發佈的事，卻放在同一張清單、而且公告沒發佈就不能發佈測驗。
4. **「演練作答」和「預覽試卷」**是兩顆按鈕，做的事很像。
5. **重要的東西藏在「⋯ 更多」**：6 顆按鈕放在一起，有的是設定（複習、詳解），有的是不可逆的動作（撤回、撤下）。
6. **分頁會出現又消失**：最多 9 個分頁（題庫編輯、試卷設定、公告、填答案、簡答批改、簡答指派、複習紀錄、統計、答案詳解），隨狀態增減，找不到東西。
7. **「測驗進行中」不一定真的在進行**：發佈後、開放時間還沒到，也顯示「測驗進行中」。

## 二、主流 App 怎麼做

| App | 值得學的做法 |
|---|---|
| **Google 表單（測驗模式）** | 永遠只有 3 個分頁：**問題／回覆／設定**。正解和配分直接在每一題旁邊設定。「何時讓作答者看到分數」是設定裡的一個選項（送出後立即／之後手動公布），不是一顆按鈕。 |
| **Canvas（學校用的課程平台）** | 設定「開放時間～截止時間」後按一次**發佈**，之後何時開始、何時截止**完全依時間自動切換**。老師可用「學生視角」實際作答，資料跟真正學生分開，有「重置測試學生」一鍵清掉。成績要按「公布成績」才給學生看。 |
| **Moodle** | 老師的「預覽」作答會被標記，**不算進成績和統計**。「作答後可以看到什麼」依階段（作答中／剛交卷／截止後）分別設定。 |
| **Google Classroom** | 作業可以「排定時間發佈」，時間到自動出現在學生的串流，**不用另外發一則公告**。 |
| **Mailchimp（電子報）** | 發送前一頁式的**檢查清單**（收件人、寄件人、主旨、內容），全部打勾「排程」按鈕才能按。 |

共通原則：

- **只有一條直線的流程**，狀態由「時間」決定，不靠管理員記得按開關。
- **對外公告跟著試卷走**，不是另一件要發佈的東西。
- **老師自己的試作永遠不算數**，也不會出現在學生看得到的地方。
- **設定歸設定、動作歸動作**：設定放在設定頁，主畫面只有「下一步」一顆按鈕。

## 三、新流程：一條直線、五個階段

```
① 準備中 ──排程──▶ ② 已排程 ──(開放時間到)──▶ ③ 作答中 ──(截止時間到)──▶ ④ 批改中 ──公布成績──▶ ⑤ 已公布
   只有管理員看得到     首頁出現預告                首頁出現「進入測驗」         首頁：「已收卷」             首頁：「查看成績」
```

管理員只需要按 **兩次**：「排程」和「公布成績」。中間的切換都依時間自動發生。

| 階段 | 會友在首頁看到 | 管理員能做的事 | 主按鈕 |
|---|---|---|---|
| ① 準備中 | 看不到 | 出題、填正解、改設定、**試作** | **排程**（清單完成才能按） |
| ② 已排程 | 預告卡片：標題、說明、開放時間，**沒有入口** | **仍可修改題目**、試作 | 取消排程（卡片消失，回到 ①） |
| ③ 作答中 | 卡片出現「進入測驗」 | 看即時作答人數；題目鎖定 | 提前結束（要確認） |
| ④ 批改中 | 「已收卷，成績公布後會通知你」；可看自己的填答、可複習（如果設定開啟） | 修正正解（分數自動重算）、批改簡答、指派批改、看統計 | **公布成績**（不可復原） |
| ⑤ 已公布 | 「查看成績」 | 看統計；全部鎖定 | 無 |

畫面最上方是這五格的**進度條**，目前階段亮起來，旁邊一句話說明「下一步要做什麼」。

### 關鍵規則

1. **首頁卡片跟著階段自動出現**：沒有「發佈預告文／撤下預告文」，也沒有獨立的「預告」。想早點讓會友知道 → 早點排程。
2. **題目可以一直改到開放作答那一刻**（① 和 ② 都能改）。所以提早排程、提早公告，不會卡住還沒出完的題目。
3. **「試作」取代「演練作答」和「預覽試卷」**：
   - 只有管理員／牧者能試作；紀錄只有自己看得到，永遠不算進成績、統計、首頁卡片。
   - 結果頁有「重新試作」；開放作答時自動清除所有試作。
4. **拿掉「自動評分」開關**：分數一律自動計算；在 ④ 修正正解時自動重新計分。會友在「公布成績」前本來就看不到分數，所以不需要這個開關。
5. **撤回的規則變簡單**：只有 ② 能「取消排程」。開放作答後就不能回頭（跟現在「有人作答就不能撤回」的結果一樣，但不用再判斷有沒有人作答）。

## 四、固定 3 個分頁（學 Google 表單）

分頁永遠是這 3 個，不會出現又消失；不能改的時候顯示成唯讀，並說明原因。

| 分頁 | 內容 | 取代現在的 |
|---|---|---|
| **題目** | 每一題旁邊直接填正解、答案詳解；上方顯示各題型題數是否符合 | 題庫編輯、填答案、答案詳解 |
| **設定** | 基本資料（標題、對應計畫）／時間（開放、截止、限時）／首頁卡片文字（有預設文字，可改）／作答規則（送出後可複習、公布成績時顯示答案詳解）／測驗宣示 | 試卷設定、公告、⋯ 更多裡的開關 |
| **作答與成績** | 統計、簡答批改、批改指派、複習紀錄（沒有資料時顯示「開放作答後會出現在這裡」） | 統計、簡答批改、簡答指派、複習紀錄 |

「⋯ 更多」整個拿掉。

### 排程前的檢查清單（只列出題的事）

- 已選擇題型並設定題數
- 各題型題目數與設定相符
- 開放、截止時間已設定，且截止在未來
- 所有題目已填正解（簡答題除外）— 選填，沒填完會提醒但不擋

「首頁卡片文字」有預設內容（用標題和時間自動產生），所以不用另外檢查。

## 六、要請你決定的事

1. **首頁卡片**：排程後就自動出現（建議），還是想保留「另外按一次才出現」？
   - 如果要「排程後過幾天才出現」，可以在設定加一個「首頁提前幾天顯示」（預設：排程後立即顯示）。
2. **題目能改到開放那一刻**（建議），還是排程後就鎖定？
3. **拿掉「自動評分」開關**，改成修正正解時自動重算（建議）？
4. **「試作」合併演練和預覽**（建議），還是仍想保留一個「只看題目、不作答」的預覽？

## 七、開發者用：實作方式與分期

現有資料欄位大多能直接對應，不需要大改資料表：

| 新階段 | 由現有欄位推算 |
|---|---|
| ① 準備中 | `status='draft'` |
| ② 已排程 | `status='published' AND now() < open_at` |
| ③ 作答中 | `status='published' AND open_at <= now() < close_at` |
| ④ 批改中 | `status='closed' AND results_published_at IS NULL`（`_exam_close_expired_papers` 每分鐘自動關閉，已存在） |
| ⑤ 已公布 | `results_published_at IS NOT NULL` |

**第 1 期：後台畫面重整（前端為主）**
- 進度條、主按鈕、固定 3 分頁、拿掉「⋯ 更多」、用語統一、準備清單拿掉公告項目。
- 題目分頁合併正解、詳解編輯。

**第 2 期：資料庫規則（migration）**
- `exam_publish`：不再要求 `announcement_published`；排程即對外顯示。首頁相關函式（`exam_home_exams`、`exam_home_banner`、`_exam_member_paper_summary`）改用「階段」判斷顯示，`announcement_published`／`pre_announcement_*` 退場（先停用、之後再刪欄位）。
- `exam_upsert_question`／`exam_upsert_paper`：放寬為 `status='draft' OR (status='published' AND now() < open_at)`；`exam_set_status('draft')` 只允許在 ② 使用。
- 試作：`is_test` 作答在所有統計、首頁、我的測驗一律排除（#296 已做首頁與我的測驗）；開放時由 `_exam_close_expired_papers` 同一支排程清除。
- 自動評分：移除 `auto_score_enabled` 開關的前端；修正正解時自動 `exam_recompute_scores`（成績公布前）。
- 新函式照慣例 `REVOKE ALL ... FROM PUBLIC, anon, authenticated` 再 GRANT；`nlc-data` allowlist 同步。

**第 3 期：清理**
- 刪除 `announcement_published`、`pre_announcement_*`、`auto_score_enabled` 欄位與相關函式；舊前端相容性評估是否需要 `forceUpdateBuiltBefore`。

**相容性**：正式環境現有 3 份試卷（2 份已公布成績 → ⑤、1 份草稿 → ①）都能直接對應到新階段，不用搬資料。其中一份已公布的卷當時關掉了自動評分（正解還沒定稿時先關），新規則下改成「批改中修正正解就自動重算」，同樣的需求不用再手動切開關。
