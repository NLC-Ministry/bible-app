# Mobile Form Control Font Size Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent iOS/mobile browser auto-zoom on every text-entry form control by enforcing a minimum 16px computed font size at the design-system and global CSS layers.

**Architecture:** Treat this as a form-control primitive issue, not an issue-report textarea issue. React form primitives (`Input`, `Textarea`, `NativeSelect`) will own the component-level class contract, while global CSS will protect vanilla-rendered controls such as `.form-control`, search inputs, inline selects, and raw `<textarea>` fields generated by `js/modules/*`.

**Tech Stack:** React 18 components in `components/ui`, vanilla ESM modules, `index.css`, Vitest static and component tests.

## Global Constraints

- Do not disable user zoom with viewport `maximum-scale`, `user-scalable=no`, or JavaScript zoom resets.
- Every focusable text-entry control must compute to at least `16px` font size on mobile: `input`, `textarea`, and `select`.
- Labels, helper text, counters, badges, buttons, checkboxes, radios, switches, and non-editable content may remain below `16px`.
- Use design-system primitives for React forms: `Input`, `Textarea`, and `NativeSelect`.
- Do not require schema, Supabase, or environment changes.
- Preserve existing uncommitted issue-report changes in `components/issue-report/ReportDrawer.tsx` and `components/issue-report/__tests__/IssueReport.test.ts`; work with them, do not revert them.
- Keep the fix broad enough to cover mobile Safari/WebKit and Chromium iOS, which share WebKit behavior.
- Follow TDD: write failing guard tests first, verify red, implement, verify green.

## Current Audit Findings

- `components/issue-report/ReportDrawer.tsx` renders the reported `description` field as a raw `<textarea>` with `text-sm`, which maps to `14px`.
- `components/ui/textarea.tsx` uses `text-sm`, so even switching to the shared component does not yet solve the auto-zoom risk.
- `components/ui/native-select.tsx` uses `text-sm`; `NativeSelect` should also be covered because iOS can zoom select controls.
- There is no shared `components/ui/input.tsx`, so React features fall back to raw `<input>` elements with ad hoc `text-sm` classes, for example `components/issue-report/AdminUsersAccordion.tsx`.
- Global CSS currently allows text selection for `input`, `textarea`, and `select`, but does not enforce a minimum text-entry font size.
- Vanilla modules generate many `.form-control` inputs and textareas, including team registration, campaign rule editor, comments/replies, flexible schedule dialogs, and care-message dialogs. These need a global safety net.

        type={type}

          className
        )}
        ref={ref}
        {...props}
      />
    )
  }
)
Input.displayName = "Input"

export { Input }
```

import { describe, expect, it } from "vitest";
import { readFileSync } from "node:fs";

const css = readFileSync("index.css", "utf8");

describe("mobile form control font-size safety", () => {
  it("defines a 16px minimum form-control text token", () => {
    expect(css).toContain("--form-control-text-size: 1rem");
  });

  it("protects textual native form controls from iOS focus zoom", () => {
    expect(css).toContain('input:not([type="checkbox"]):not([type="radio"]):not([type="range"]):not([type="color"])');
    expect(css).toContain("textarea");
    expect(css).toContain("select");
    expect(css).toContain("font-size: var(--form-control-text-size)");
  });

  it("protects app-specific vanilla form-control classes", () => {
    [
      ".form-control",
      ".reader-search-input",
      "#plan-search-input",
      ".inline-select",
      ".reader-select-compact",
      ".announcement-form-panel__input",
      ".announcement-form-panel__textarea",
      ".devotional-textarea"
    ].forEach((selector) => {
      expect(css).toContain(selector);
    });
  });

  it("does not disable user scaling as an auto-zoom workaround", () => {
    const html = readFileSync("index.html", "utf8");
    expect(html).not.toMatch(/maximum-scale\s*=\s*1/i);
    expect(html).not.toMatch(/user-scalable\s*=\s*no/i);
  });
});
```
