# 小測驗、快問快答後台重新設計

> 狀態：**設計已確認，待實作**（2026-09-27）。總覽 issue 見 GitHub。
> 與大測驗重新設計（`docs/exam-flow-redesign-design.md`）共用同一套用語與原則。

## 一、三種測驗共用的原則

| 原則 | 說明 |
|---|---|
| 狀態依時間自動切換 | 準備中 → 已排程 → 作答中 → 已結束（大測驗多一個「已公布」） |
| 往回只有一種動作 | 「取消排程」，只能在開始前用；開始後題目鎖定 |
| 試作 | 管理員自己作答一次，不留紀錄、不算數、別人看不到 |
| 測試在 staging | 正式環境不放測試用工具（「僅系統管理員」範圍、「清除作答」） |
| 日曆式管理 | 主畫面是「接下來的日期」清單，一眼看出哪天準備好、哪天缺題 |

參考：Duolingo／Wordle（每日挑戰自動出現）、Buffer／Hootsuite（排進佇列、時間到自動發）、Google Classroom（一次排好多天）、Canvas（依時間切換、學生身分試作）。

## 二、小測驗

### 現況（正式環境 2026-08-14～09-17）
- 1,123 次發佈：系統管理員 1 人發了 1,108 次；小組長 7 人 8 次、牧區長 5 人 7 次；排程 0 次；「僅系統管理員（測試用）」0 次。
- 每天要有人手動：選日期 → 選範圍 → 選 A／B／自訂 → 發佈。忘了就沒有測驗。
- AI 在**當天 00:05** 才產生當天題目。

### 已確認的決定
1. A／B 兩版只是備用 → **改成一版，不滿意就「換一版」**
2. 小組長、牧區長自行發佈 → **拿掉**，他們只看統計
3. 自動發佈時間 → **每天 00:00 發佈、23:59 截止**

### 新流程
- 每個計畫**設定一次**「自動發佈規則」：開／關、00:00～23:59、發給全部小組、使用 AI 題目。
- **AI 提前一天出題**（前一天中午產生隔天題目），讓管理員有半天可以看題、換題；前一天 20:00 還沒有題目就通知管理員。
- 00:00 由排程自動發佈給全部小組。
- 後台主畫面：**未來 7 天日曆**，每天一格：

  | 狀態 | 意思 |
  |---|---|
  | 等待出題 | AI 還沒產生（前一天中午才會有） |
  | 已排程（AI 題目／自訂題目） | 00:00 會自動發佈 |
  | 這天不發 | 管理員手動略過 |
  | 作答中 | 今天，顯示即時完成率 |
  | 已結束 | 顯示完成率、平均分數 |

- 點進某一天：看題目、**換一版**、**改成自訂題目**（沿用現有文字匯入）、**試作**、**這天不發**。
- 分頁三個：**日曆／規則設定／統計**。
- 會友端不變：讀完當天進度才能作答。

## 三、快問快答

### 現況
- 正式環境 3 題（1 已發布、2 草稿）、32 筆作答；固定**每週一、三、五**。
- 狀態：測試中（其實是草稿，沒人能作答）→ 已發布（再分即將開始／進行中／已結束）→ 已下架；往回有取消發布、下架、重新上架三種。
- 改已開始的題目會自動另存新題，列表出現看似重複的題目。
- 「清除作答」會刪掉會友當天的所有作答。
- 統計以「天」為單位（每日明細、每日趨勢、排行榜、CSV）。
- 題目一題一題在表單裡編輯。

### 已確認的需求
1. 固定每週一、三、五
2. **統計以週為單位**
3. **題目可以從文字直接匯入**

### 新流程
- **狀態**：準備中 → 已排程 → 作答中 → 已結束。拿掉「下架／重新上架／取消發布」，只留開始前的「取消排程」。
- **開始後鎖定**；要沿用就按「複製成新題」（取代自動另存）。
- 「預覽」改名「**試作**」；「清除作答」從正式環境拿掉。
- **排程規則**：每週一、三、五，預設時段（在規則設定裡改，例如 07:00～10:00）。
- 後台主畫面：**接下來 4 週的一三五日曆**，空的格子標「缺題」。
- **文字匯入**：沿用小測驗的格式，一次貼多題，**自動依序填進接下來空著的一、三、五**；想指定日期就在題目上方加一行 `日期：10/5`，想改時段加 `時段：12:00-13:00`。匯入前先顯示「哪一題會排在哪一天」讓你確認。

  ```
  [單選] 亞伯拉罕原本住在哪座城市？
  A. 哈蘭
  B. 吾珥
  答案：B

  日期：10/9
  [是非] 摩西在米甸住了四十年。
  答案：對
  ```

- **週統計**（週一到週日，一週 3 題）：
  - 參與人數與參與率（這週至少答 1 題）
  - 3 題全答的人數
  - 平均答對率
  - 大區／牧區比較
  - 週排行榜（答對題數 → 總用時）
  - 每週趨勢圖、每週 CSV
  - 點進某一週再看每一天的明細（保留現有每日明細）

## 四、開發者用：實作要點

### 小測驗
- 新表 `quiz_auto_publish_rules`（`global_plan_id`、`enabled`、`publish_time`、`close_time`、`created_by`、`updated_at`）與每日覆寫（略過、改用自訂題目）；或在 `daily_quizzes` 加 `skip`／`source` 欄位——實作 issue 再定。
- 發佈：pg_cron 在 00:00（台灣）對每個啟用規則的計畫呼叫現有發佈邏輯，範圍固定全部小組；冪等（重跑不重複發佈）。
- 出題：`generate-daily-quizzes` 改為前一天 12:00 產生隔天、只產生一版；20:00 檢查缺題並寫入管理員通知。
- 權限：`publish_daily_quiz`／`schedule_daily_quiz_publish` 收回給 service_role／admin；拿掉 `scopeType='admin'`。
- 舊的 `quiz_publication_schedules`（0 筆）與 B 版相關程式在清理 issue 移除。
- 新函式照慣例 `REVOKE ALL ... FROM PUBLIC, anon, authenticated` 再 GRANT；`nlc-data` allowlist 同步。

### 快問快答
- `lightning_quiz_questions.status` 只留 `draft`／`scheduled`，作答中／已結束由 `rise_date`＋時段推算；`archived` 退場（正式環境目前 0 筆）。
- 取代 `_lightning_quiz_is_locked` 的自動 fork：開始後拒絕修改，另提供 `admin_copy_lightning_quiz_question`。
- `admin_clear_lightning_quiz_attempts` 從 `nlc-data` allowlist 與前端移除。
- 新表或設定：排程規則（星期、預設時段）。
- 匯入：`quiz-import.mjs` 加 `日期：`／`時段：` 前置行的解析，單題限制沿用快問快答題型；批次寫入用一支 RPC（全部成功或全部失敗）。
- 週統計：新 RPC 以 ISO 週（週一起）彙總；前端 `lightning-quiz-analytics.mjs` 加週彙總與 CSV。
